# Raster drawing preparation and inspection

Implemented 14 November 2026 as a Python package and standalone CLI. It creates
reusable raster artifacts for the [roadmap](ROADMAP.md): an original source,
smaller overviews, suggested drawing/context regions, optional local OCR, and
detail crops whose coordinates map back to the source.

This component makes no model/API requests. It does not answer questions, count
objects, segment rooms, calculate areas, or establish physical scale. The
[image candidate API](../image_api/README.md#raster-preprocessing-in-the-candidate-path)
uses it for internal preparation with OCR off. Actual API token/cost savings have
not been measured.

## Install and prepare

Run from the repository root using the project's virtual environment. The
standalone requirements install Pydantic, Pillow and NumPy. No IFC, inference SDK,
GPU, OCR engine, or model key is needed when running from the checkout. The full
project's `preprocess` extra is another option for an already installed project.

Windows PowerShell:

```powershell
.\.venv\Scripts\python.exe -m pip install -r drawing_preprocessor/requirements.txt
.\.venv\Scripts\python.exe -m drawing_preprocessor prepare "dataset/junction-dataset/data/swiss_dwellings/site765_bldg1658_floor7457.png" --output build/prepared
```

Linux:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r drawing_preprocessor/requirements.txt
.venv/bin/python -m drawing_preprocessor prepare dataset/junction-dataset/data/swiss_dwellings/site765_bldg1658_floor7457.png --output build/prepared
```

With the full project installed, console entry point `drawing-preprocess` offers the same subcommands. Source
archives are optional and are not distributed with the Python package. Adjust
the sample path to the actual dataset root.

Preparation prints JSON containing `manifest` (its output path) and `prepared`
(the validated manifest contents). No credential is needed. Useful switches are
`--overview-long-edge` (default 1600), `--analysis-long-edge` (1200), `--padding`
(12 source pixels), and `--source-uri` (a caller-supplied resource identifier;
otherwise the source filename). Overviews are reduced only, never enlarged.
The default source limit is 50 million pixels; `--max-source-pixels` changes the
explicit pixel limit. Encoded inputs are also bounded to 128 MiB. PNG, JPEG,
WebP, BMP, and single-page TIFF are supported. Render
PDF pages or split multi-page/animated inputs before calling this component.

## Artifacts and cache

Each preparation is stored below `build/prepared/prepared-<identity>/` by default:

```text
manifest.json                 PreparedDrawing contract
checksums.json                Published-artifact hash inventory
original.<source-extension>   Byte-for-byte source copy
source.png                    Full-resolution RGB source in the declared frame
layout.png                    Debug image of suggested region boxes
regions/
  000-overview.png            Reduced full-source overview
  001.png                    First suggested full-resolution crop, if any
  001-overview.png            Its overview
  ...
inspections/
  <identity>.png             Later on-demand detail crops
```

Artifact URIs in the manifest are relative to its directory, use forward slashes,
and are not browser URLs. The host can serve them through resource endpoints.
`build/` is ignored by Git; source drawings are never overwritten.
The host must bind `source_uri`/source hash to its licensed source catalog and
retain the original attribution/license when serving or sharing derived images.

Cache identity includes the source SHA-256, configuration, pipeline version,
Pillow/NumPy versions, requested OCR engine version and language-data hashes, and source URI. Existing
prepared artifacts are reused after checksum validation. Changed source/config
produces a different identity. A damaged artifact set can be regenerated by
preparing again. `load_manifest()` validates the manifest and required artifact
hashes; on-demand inspection outputs include their own SHA-256 in the response.

The [Python models](../contracts/models.py) are the source of truth for
`PreparedDrawing`, `PreparedRegion`, OCR records, and `InspectRegionArgs`. The
generated [JSON Schema](../contracts/jsonschema/PreparedDrawing.schema.json) and
[TypeScript](../frontend/src/contracts/PreparedDrawing.ts) support consumers.
These are preparation artifacts, not a populated construction knowledge bundle
or a `QueryResult` proving an answer.

## Regions and coordinate frames

Every preparation retains a `full_source` region. Other roles are
`drawing_candidate`, `context_candidate`, or `unknown`. Background contrast,
whitespace bands, and analysis-only suppression of thin long rules suggest the
boxes. Shallow bands remain together to preserve header/footer and legend
context. A large candidate is not thereby a verified floor plan; smaller ones
are not necessarily headers. Low-confidence layout situations retain the full
image, and warnings explain the fallback.

The stored source copy preserves all original bytes. `source.png` decodes the
original **stored pixel orientation**, ignores EXIF auto-rotation, and composites
transparency on white. A non-default EXIF orientation produces a warning. Use
the generated PNGs for display/inference so browser or model auto-orientation of
the original JPEG cannot silently disagree with the declared frame.

`source_bbox` is `[left, top, right, bottom]` with a top-left origin, X increasing
rightward, Y downward, and half-open right/bottom bounds. Source, crop, and
overview frames have separate IDs. Their matrices use homogeneous column
vectors, matching the [shared coordinate convention](SCHEMA.md#geometry-and-measurement):

```text
source_point = region.to_source × [view_x, view_y, 1]
source_point = region.overview_to_source × [overview_x, overview_y, 1]
```

The overview transform uses actual resulting width/height, including resize
rounding. These are presentation-pixel transforms. They supply no metres-per-pixel
calibration; reading a printed scale label does not establish one either.
Low-contrast features, page noise, and unusual layouts can defeat heuristics.
Always retain access to the full source, not only the cropped overview.

## Inspect a detail

Use a region ID from the manifest, not a guessed ID. Coordinates default to that
region's full-resolution local pixels. Specify `--coordinate-space overview` if
the box was selected on its overview instead. Bounds must lie inside the
selected image; unknown IDs and invalid/out-of-bounds boxes are rejected.

This PowerShell example prepares the Swiss source, selects its full-source
region, and crops the lower-page scale/legend context:

```powershell
$prepared = .\.venv\Scripts\python.exe -m drawing_preprocessor prepare "dataset/junction-dataset/data/swiss_dwellings/site765_bldg1658_floor7457.png" --output build/prepared | ConvertFrom-Json
$viewId = $prepared.prepared.regions[0].id
.\.venv\Scripts\python.exe -m drawing_preprocessor inspect $prepared.manifest --view-id $viewId --bbox 580 2290 1000 2420
```

For other sources/views, choose a box using their declared dimensions. On Linux,
use `.venv/bin/python`; copy the returned manifest path and view ID into the
`inspect` command. `--output-long-edge` optionally reduces the returned detail;
without it, the crop preserves full source resolution. Fractional bounds round
outward to source pixels, staying within the registered region.

The JSON result contains the crop's relative `image_uri`, hash, dimensions,
`source_bbox`, frame IDs, and `to_source` matrix. `ocr_spans` includes existing
source-frame OCR words overlapping the crop. Inspection does not rerun OCR or
change those word boxes into crop coordinates.

## Optional local OCR

OCR defaults to `none`. To request the Tesseract adapter:

```powershell
.\.venv\Scripts\python.exe -m drawing_preprocessor prepare "drawing.png" --output build/prepared --ocr tesseract --ocr-languages eng+fin --ocr-timeout 30
```

OCR is an optional source-text aid; preparation, region detection and inspection
work identically without it. On Windows, the reproducible local setup is:

```powershell
.\.venv\Scripts\python.exe scripts/setup_tesseract.py
.\.venv\Scripts\python.exe scripts/setup_tesseract.py --check
```

This downloads a pinned, SHA-256-verified official Windows package and extracts
its engine into ignored `.tools/tesseract/` using a verified local 7-Zip helper.
The Tesseract installer is not executed. It installs official `tessdata_fast`
4.1.0 language data for `eng`, `fin`, `deu`, `fra`, `ita`, and `swe`; use
`--languages eng fin` to request a smaller set. Download URLs, hashes, and observed
engine version are recorded in local `setup-provenance.json`. The setup requires
network access, but subsequent preprocessing and OCR are local.

On Debian/Ubuntu:

```sh
sudo apt install tesseract-ocr tesseract-ocr-eng tesseract-ocr-fin
tesseract --version
tesseract --list-langs
```

Other optional language packages follow the same naming pattern, for example
`tesseract-ocr-deu`, `tesseract-ocr-fra`, `tesseract-ocr-ita`, `tesseract-ocr-swe`.
The core module has no operating-system-specific execution path. Windows was
tested here; these Linux setup instructions have not been executed in this pass.

Discovery prefers backend `TESSERACT_CMD`, then `PATH`, then the Windows local
setup. `TESSDATA_PREFIX` can explicitly select language data. Python dependency
installation alone does not install the engine/data, and `pytesseract` is not
required: this adapter calls the executable directly. Upstream references:
[installation guide](https://tesseract-ocr.github.io/tessdoc/Installation.html),
[Windows distribution](https://github.com/UB-Mannheim/tesseract/wiki),
[official language data](https://github.com/tesseract-ocr/tessdata_fast/tree/4.1.0).

The adapter uses
local sparse-text recognition and parses word-level TSV into original text,
source-pixel boxes, and engine recognition confidence. It preserves identifiers
as strings; it does not normalize `5.10`, parse title-block fields, recover
arbitrary text rotations, interpret legends, or validate dimension/scale meaning.

| OCR status | Meaning |
|---|---|
| `not_requested` | No OCR was run |
| `unavailable` | Requested executable/version was unavailable |
| `failed` | OCR timed out or failed; image artifacts remain usable |
| `partial` | Recognition returned malformed/out-of-bounds records that were omitted |
| `complete` | The engine invocation and TSV processing completed; text accuracy/completeness is not established |

An unavailable/failed result is distinct from successful recognition returning
no words. A recognition confidence is not a calibrated probability of source
truth. Preparation can succeed while OCR is unavailable or failed; check
`warnings` and status before using OCR. Failed OCR is retried on preparation.
Installing an absent executable or changing the selected language files changes
the cache identity. Word OCR is not a general document-layout or handwriting
solution. In a live Windows check, Tesseract 5.5.3 returned room `5.10` and the
printed `1:200` labels from the Swiss sample; output on a symbol-heavy CubiCasa
sample was mostly irrelevant. These two observations do not establish accuracy
on a question family. Keep OCR off unless it supplies useful text for the task.

## Human review gallery

```text
python -m drawing_preprocessor review dataset/junction-dataset --output build/preprocess-review --count 50 --seed 20261114
```

Use the configured Windows/Linux interpreter above. This samples PNG/JPEG files
randomly within source folders and balances selection across folders, deduplicates
identical bytes, and prepares a static `index.html` with relative artifact links.
It accepts either a dataset root containing `data/` or `data/` itself. Defaults
leave OCR off; add `--ocr tesseract --ocr-languages eng+fin` to compare its text
extraction on a separate run. Individual preparation failures remain in the
sample and get error cards. This is diagnostic sampling, not corpus-weighted QA
evaluation, and it reads no reference answers.

Serve the existing gallery on Windows or Linux, using the configured interpreter:

```text
python -m drawing_preprocessor serve build/preprocess-review --port 8765
```

Open <http://127.0.0.1:8765/> and leave the command running during review. Stop it
with Ctrl+C when finished. The server binds only to loopback and reads files
within this gallery directory; it provides no directory listings or file writes.
For this checkout's prepared 50-image set, use `build/preprocess-review-50`.

Use HTTP rather than a direct local-file link. In the initial Windows review,
HTML was readable but staged image files had restrictive temporary-file ACLs,
so Firefox displayed only alternative text. The local server reads the artifacts
and delivers their bytes over HTTP without changing Firefox security settings.
Missing images now display an explicit loading error instead of a blank preview.

Compare the original overview and layout boxes with
each candidate crop; inspect native detail through the image links. Check for
clipped notes/symbols, lost footer context, merged/separated views, and unreadable
downscaling. OCR runs include optional source-coordinate word-box overlays and
raw words. Mark pass/problem/uncertain and add notes. Browser storage retains
labels when available; **Download review JSON** preserves them for sharing.
Browser storage is separate for file and HTTP origins: if you already entered
ratings in the old file page, download its JSON there, then use **Import review
JSON** in the HTTP gallery. Import validates the review ID and every source
path/hash before changing anything, and preserves conflicting existing ratings.
Changing the produced artifact set changes the review identity, so prior labels
are not silently assigned to a new OCR/configuration run.

`sample.json` records the seed, configuration, source hashes and outcomes. Source
attribution/license catalogs are copied into the review directory when present.
Original assets stay unchanged. The seed-20261114 50-image no-OCR run prepared on
14 November is at `build/preprocess-review-50/index.html` in this checkout.

## Backend tool integration

### Image candidate service

The image API first applies its existing `prepare_image` rules: verify accepted
upload/decoded sizes, apply EXIF orientation, composite transparency on white,
and create a metadata-free upright PNG at the full display dimensions. It then
passes that canonical PNG to this package, with OCR disabled. Consequently, the
API's internal prepared source already has the correct upright orientation;
the standalone stored-pixel/EXIF convention above does not undo that orientation.

`IMAGE_API_PREPROCESS_MODE` controls this service integration:

- `original` (default): prepare/cache derived artifacts but send the unchanged
  canonical PNG to the model.
- `overview`: send the `full_source` region's reduced overview, preserving all
  page panels, footers, legends and their relative positions. No inferred main
  region or individual candidate crop is automatically selected.
- `off`: skip this package and use the existing canonical PNG path.

`IMAGE_API_PREPROCESS_OVERVIEW_LONG_EDGE` defaults to 1600, and
`IMAGE_API_PREPROCESS_CACHE_ENTRIES` defaults to 8. The service owns a bounded
session cache in a `TemporaryDirectory`, deleted at backend shutdown. This is
separate from user-chosen persistent CLI output below `build/`; persistent API
upload storage is not enabled. The API's existing 20 MiB upload/prepared-image
and 40-million-pixel default decoded limits still apply; this module's larger
standalone input limits do not relax them.

The API retains the submitted hash and full display dimensions, maps boxes from
the actual model image back to those display coordinates, and identifies that
model image with `image.inference_sha256`. Its internal manifest describes the
canonical PNG, rather than changing the public identity of the submitted upload.
Optional `provenance.preprocessing` records `mode`, `pipeline_version`,
`prepared_id`, `input_width`, and `input_height`. Preparation time/cache reuse are
reported as `metrics.preparation_ms` and `metrics.preparation_cache_hit`.
Internal artifact paths are not returned by this endpoint. The frontend retains
its original submitted snapshot for display and evidence overlays; no new upload
or review flow is required.

This path does not invoke OCR, register an agent tool loop, inspect IFC, or
produce final counts/answers. Reducing image resolution remains a quality/cost
tradeoff to evaluate on actual questions.

### Registered-view inspection adapter

Preparation is an ingestion call made by the host. The supplied backend adapter
exposes only registered-view detail inspection to a model:

```python
from drawing_preprocessor.tools import inspection_tool_spec, execute_inspection_tool

tool_declaration = inspection_tool_spec()
# The host resolves this trusted manifest from its own asset/view registry.
result = execute_inspection_tool(manifest_path, {
    "view_id": selected_view_id,
    "bbox": [10, 20, 180, 160],
    "coordinate_space": "view",
})
```

`python -m drawing_preprocessor tool-schema` prints the function declaration.
Arguments are validated by `InspectRegionArgs` and contain no filesystem path.
The host supplies the trusted manifest; a caller cannot select arbitrary source
files through model arguments. Return structured tool output and resolve the
crop artifact for a subsequent supported image input or the evidence UI.

This adapter is ready for registration, but no agent tool loop or live Nemotron
tool-call verification is supplied by this package. The image candidate service
uses ingestion only; it does not expose this inspection adapter as an HTTP/model
tool. The adapter does not execute model-generated code.

## Verification and limitations

A manual layout check on 14 November 2026 used the supplied Swiss
`site765_bldg1658_floor7457.png` (1753 × 2480 pixels). Default settings proposed:

- Main candidate: `(614, 349, 1141, 1883)`.
- Context candidate containing footer/legend/title: `(66, 2162, 1708, 2433)`.

The full-source region remains available alongside these suggestions. The layout
step took approximately 0.11 seconds in one observation. This is a dated example,
not a layout-accuracy benchmark, typical-latency claim, OCR-quality result, or
API-cost measurement. Dense/noisy scans and low-contrast content need further
evaluation; a view may contain multiple scales or floor plans.

Run the focused tests from the repository root:

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_drawing_preprocessor -v
```

Use `.venv/bin/python` on Linux. Fixture, transform, error, and mocked OCR tests
check the component's invariants; they do not establish end-to-end question
accuracy. Metric area/length measurement and room-boundary reconstruction remain
separate work requiring source-backed calibration and geometry.
